Text a scraper can't read

The paragraph below is stored in the DOM as a substitution cipher. A font built in your browser at page load maps the scrambled codepoints back to the right glyph outlines, so you read the original words while innerText hands out nonsense.

What this actually buys you

Stops

Bulk text extraction: fetch plus an HTML parse, innerText scraping, copy-paste into a chat window. The server-rendered HTML is scrambled too, so crawlers that never run JavaScript get nothing readable.

Does not stop

A determined adversary. The generated font is downloadable and its cmap describes the substitution completely — anyone willing to parse it can invert the cipher. Rendering the page and running OCR also defeats it.

Costs you

Screen-reader output, in-page search, and copy-paste on protected text. That is the same mechanism, not a bug. Protect article bodies; leave navigation, headings, and anything assistive technology needs alone.
