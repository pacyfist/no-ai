# Design: the showcase page — Three Gates, Five Stages

Date: 2026-08-08
Status: approved, not implemented
Supersedes: docs/superpowers/specs/2026-08-07-demo-github-pages-design.md

## Amendment, 2026-08-08: the build guard is gone

This spec was written while `scripts/verify-static-build.mjs` existed, and refers
to it in several places — including a recommendation to extend it. **That script
has been deleted.** Browser verification moved to Playwright (`e2e/`, run with
`npm run e2e`), which runs against the built static site under the real `/no-ai/`
base path and now gates the deploy in CI.

Read every reference to the guard below as referring to `e2e/` instead, with one
exception that no longer holds: the guard's check that the specimen's plaintext
stays pinned to **at most one JS chunk** has no end-to-end equivalent, because
Playwright observes the rendered page rather than the build artifacts. The
`index.html` plaintext assertion survives, in `e2e/protection.spec.ts`.

Where the spec says the page may disclose that its specimen's plaintext lives in
one bundle chunk "because the guard pins it there", the disclosure is still true
but is no longer machine-enforced.

## Problem

The shipped page shows the library's features but does not present them. Seven
peer sections arrive in an order that serves the author rather than the reader:
the header concedes the whole trick in prose before anything is demonstrated,
implementer telemetry is the second thing on the page, three template APIs and
`EnvironmentInjector` internals sit between the visitor and "what does this buy
me", and the adoption facts a developer needs first — peer range, licence,
what static hosting costs — are scattered across the bottom third or absent.

The goal is a page that shows every feature, is interactive, and lets a
developer reach a _correct_ adoption decision quickly — including a fast no.

## Verified defects in the current page

Found by the design review and confirmed against this workspace and the live
deployment. These are real, independent of which design wins.

1. **The demo's own article ships readable in a JS chunk.** `verify-static-build.mjs`
   greps `index.html` only; the specimen is template content, so it lands in
   `main-*.js` in plaintext. Confirmed: `grep -l "quick brown fox" dist/demo/browser/*.js`
   matches. The page's central claim is that its text is not readable, and a
   sceptic's first move is to view source.
2. **The "Pinned cipher" card's copy is false on this build.** It reads "Reload
   the page: this card keeps the same substitution while the rest of the page
   draws a new one." Prerendering bakes one seed, so the rest of the page does
   not draw a new one. Confirmed: `noAiSeed` is `233441430` on every load of the
   live site.
3. **The page has drifted from the README.** The README lists the missing
   `kern`/`GPOS` table as a cost; `tradeoffs-section.ts` does not mention it.
   Two sources of truth for the page's most important honesty content.
4. **The paste check is inverted for partial selections.** `proof-section.ts`
   compares the pasted string to the whole article, so any partial copy — the
   common case — is labelled "unusable" when it is in fact scrambled correctly.
5. **`config-card` hides readable text from assistive technology.** `aria-hidden`
   is unconditional, so the kill-switch card's genuinely unprotected text is
   hidden for no reason, contradicting the page's own stated principle.
6. **The reveal toggle's framing is wrong.** It reads as page-wide but reaches
   only the shell's service, never the config-lab child injectors.

## How this design was chosen

Eleven agents: three enumerating the library's feature surface, diagnosing the
current page, and modelling an evaluating developer's questions; four producing
committed, non-hedged designs from different angles; three scoring all four
comparatively through one lens each; one synthesising.

The panel did not agree. Each lens crowned a different design and the totals
were near-tied:

| Design                              | Coverage | Usefulness | Buildability | Total  |
| ----------------------------------- | -------- | ---------- | ------------ | ------ |
| Take It Apart (teardown)            | 8        | 5          | 9            | **22** |
| Prove It Yourself (evidence ladder) | 9        | 6          | 6            | 21     |
| Verdict First (adoption decision)   | 7        | 9          | 5            | 21     |
| The Bench (one live instance)       | 6        | 7          | 8            | 21     |

Take It Apart is the base. Its decisive property is structural: the interactive
spine runs on the exported framework-free core — `buildScrambleMap`,
`scrambleText`, `invertScrambleMap`, `parseBaseFont`, `forgeScrambledFont` —
with no `EnvironmentInjector` and no `NoAiFontService`, so it touches the shared
`SEED_KEY` zero times. The `TransferState` hazard stops being a design tax
instead of something routed around with `@defer`.

Its two scored defects were grafted away rather than rewritten: the adoption
facts were scattered (fixed by hoisting Verdict First's three gates into the
masthead) and search-engine indexing was absent (fixed by grafting the "what a
search index would store" pane into Stage 1).

## Build order

Each stage leaves the page deployable, and `npm run verify:static` must pass at
every one.

0. **Guard first.** Close the plaintext-in-JS hole and fix the six verified
   defects above. Independent of the redesign and worth shipping alone.
1. Masthead gates, `#see-it` with the selection mirror, `#stage-1-dom` —
   reusing `proof-section`'s specimen machinery.
2. `#stage-5-ssr` and `#break-it` attack A — reusing `raw-html-section`'s fetch.
3. `#costs` as a checklist over the existing tradeoffs content.
4. The cipher and forge benches (`#stage-2-cipher`, `#stage-3-font`).
5. `#knobs`, `#verdict`, `#adopt`; retire `api-section` into `#stage-4-angular`.

## The design

Base = Proposal 4 (Take It Apart). It won on raw score (22 vs 21/21/21), took the buildability lens outright (9/10), and is the only design that dissolves the hardest constraint instead of routing around it: Stages 2-3 and Break-it run entirely on the exported framework-free core (buildScrambleMap / scrambleText / invertScrambleMap / parseBaseFont / forgeScrambledFont) with NO EnvironmentInjector and NO NoAiFontService, so they touch the module-level SEED_KEY zero times and constraint 5 stops being a design tax on the page's centre of gravity. It is also the only proposal that got the reflow physics right (verified: font-forge.ts:65 copies the READABLE glyph's advanceWidth onto the SCRAMBLED codepoint, so protected-vs-revealed DOES reflow) and the only one whose riskiest demo shipped with a three-deep fallback plan.

Its two named defects are both grafts, not rewrites. Defect 1 — the decision judge scored it 5/10 because the adoption facts are scattered across positions 8, 11 and inside Stage 5, reproducing the very flaw the audit found in the current page. Fixed by hoisting Proposal 2's gates to the masthead: three unmissable rows (Angular ^21.2.0 peer range, AGPL-3.0-only §13, rendering mode) that can deliver a correct NO in thirty seconds. Defect 2 — search-engine indexing appears nowhere, and it is the evaluating developer's priority-1 question and a named distrust trigger. Fixed by grafting Proposal 2's "what a search index would store" pane into Stage 1.

Grafted in from the steal lists: the zero-click selection mirror and the self-calibrating search (P1), @defer (on interaction) instead of (on viewport) (P1), Proposal 3's deep links from every cost row to the control that proves it, Proposal 3's sequential one-instance collision demo, Proposal 2's build-guard extensions (grep .js chunks; count data-no-ai-ssr elements), and P4's own live PASS/FAIL prerender assertions.

Dropped, per the must-not-survive lists: P1's whole-page shell.failed.set() sabotage and its instruction to freeze the library API; P1's cmap-reading attack route B (provably broken — glyph names are uni<scrambled> and the cmap maps scrambled→outline, so it never reveals which readable letter an outline draws); P2's verdict-pill questionnaire and its Node pre-scramble prebuild; P2/P3's "lines reflowed: 0" across the reveal toggle; P3's one-instance-only architecture; and P4's own plaintext sandbox baked into the prerendered HTML and its simultaneous two-face collision demo.

Net shape: 11 anchored sections, two shared benches, one conventional gallery that reuses existing config-lab code, and one narrative track. Gates first, mechanism in teaching order, self-defeat before the verdict, install last.

## Page spine

### 1. 0. Masthead + three gates (#top)

**Purpose.** Name the product in one unhedged line and put the three disqualifiers in the first screen, so a reader who is not a candidate can leave in thirty seconds without having been sold anything first. This is the graft that fixes the base proposal's worst flaw.

**Interaction.** Static, deliberately. No questionnaire, no computed verdict pill (the decision judge named that instrument as manipulative and unable to know whether the reader is scouting for next year). Identity line: 'An Angular 21 library. Not encryption. It raises the cost of bulk scraping.' Fact chips: v0.0.1 - peers @angular/core ^21.2.0 + opentype.js ^2.0.0 - AGPL-3.0-only - not on npm, git install only - requires FontFace + document.fonts.add. Then three gate rows the reader self-selects against. GATE 1 FRAMEWORK: the peer range as a number, and 'not Angular? the cipher and the forge are framework-free — go to #stage-2-cipher and #adopt.' GATE 2 LICENCE: AGPL §13 in one actionable sentence (serving a public page that uses this puts that site's source under the same terms) plus an explicit yes/no on whether a commercial licence exists. GATE 3 RENDERING: a three-row table — per-request SSR / static prerender / client-only — columns 'what the served HTML contains', 'where the seed lives', 'what one crawl costs an attacker', 'verdict'. The static-prerender row is marked 'this page, right now' and links to #stage-5-ssr where the claim is proved live. Two jump links: 'show me' -> #see-it, 'break it' -> #break-it.

**Features shown:** config.seed (as this deployment's condition); FAILURE: prerendering bakes one seed for every visitor; COST: AGPL-3.0-only network clause; COST: opentype.js is a required peer dependency

### 2. 1. See it once (#see-it)

**Purpose.** Deliver the payoff in under three seconds using the visitor's own hand, before a word of mechanism, so the five stages have something real to take apart.

**Interaction.** One protected specimen of realistic article length (~700 words, mixed case, numerals, punctuation, an em dash, accented letters, one emoji) at real body size and measure — rendered by <p [noAi]> so it genuinely prerenders. Directly beneath it, an empty monospace box labelled 'drag across any line above'. A document selectionchange listener streams getSelection().toString() into it live, character by character. No button, no clipboard permission, no instruction beyond four words, and — critically — the plaintext is only ever on screen, so nothing readable enters the served HTML. Below that, ONE reveal control, scoped by its own label: 'Repaint this section in plain Roboto — the characters will not change.' Two counters beside it that do not move when it flips: DOM character count and a digest of the element's textContent. The caption states the thing every other proposal got backwards: the line breaks DO move when you reveal, and that is the proof the forged font was carrying the plaintext's advance widths all along.

**Features shown:** NoAiDirective — bound form [noAi]; service.revealed (and that it does not change scramble()); service.fontStack; COST: copy-paste yields ciphertext; Advance widths preserved glyph-for-glyph (via reveal-time reflow)

### 3. 2. Stage 1 — What lands in the DOM (#stage-1-dom)

**Purpose.** Consolidate the current page's four scattered proofs of one fact into one place where each instrument is a different machine reading the same element — and answer the evaluating developer's priority-1 question (search indexing) here, from the live DOM, rather than nowhere.

**Interaction.** Live outerHTML readout of the #see-it element, refreshed by MutationObserver, with the inline style attribute and the data-no-ai-ssr attribute highlighted and labelled. Then four instruments. (a) SELF-CALIBRATING SEARCH: one input, 'type any word you can see in the paragraph above' -> 0 hits against document.body.innerText; then 'now type a word from this sentence' -> hits, listed. The visitor supplies the plaintext from their own eyes, so the page never names it, which is both safer under constraint 3 and more convincing. Ctrl+F offered as the same test run by the browser. (b) PASTE BOX, rewritten: reports character count, word-length signature match, and whether every pasted codepoint is inside the current charset — replacing the exact-string equality that today mislabels any partial selection as 'unusable'. (c) WHAT AN innerText SCRAPER GETS: document.querySelector('.protected-body').innerText printed live. (d) WHAT A SEARCH INDEX WOULD STORE: title, meta description and headings printed readable, body printed as ciphertext, with the unhedged sentence that protected text is not indexed even by JS-executing crawlers, the protect-the-body/keep-the-head recipe, and a direct answer on cloaking risk in the author's own words. Closing note, stated plainly rather than hidden: this specimen's plaintext lives in one JS chunk because it is template content; on a real site the article body arrives from your CMS as data, and the build guard pins where it is allowed to appear.

**Features shown:** Inline styles only — no stylesheet to import; data-no-ai-ssr marker; COST: find-in-page does not match; COST: copy-paste yields ciphertext; SEO / search indexing; Space is never ciphered, line breaking survives

### 4. 3. Stage 2 — The cipher (#stage-2-cipher)

**Purpose.** Teach that step one is a plain, seeded, reversible substitution the reader can compute themselves, and prove the framework-free core by using it. Instantiates NO NoAiFontService and NO child injector, so it is immune to constraint 5 and constraint 6 by construction.

**Interaction.** THE CIPHER BENCH, wrapped in @defer (on immediate) with a skeleton placeholder — deferred blocks render only the placeholder during prerender, so no bench prose reaches index.html (this is what replaces the base proposal's plaintext 'sandbox specimen', which the decision judge correctly flagged as a view-source trust risk). On the client it triggers immediately, so it is effectively above the fold. Controls: an editable textarea (default text populated client-side only), a seed field with a 'draw a new seed' button (randomSeed), and a charset picker — printable ASCII (DEFAULT_CHARSET) / digits only / letters only / add 0x4e2d / custom hex list / one codepoint. Live outputs: ciphertext beside the input updating per keystroke (scrambleText), charset size, glyph budget (charset+1), a 'fixed points: 0 / N' counter recomputed on every reseed, a collapsible full substitution table (readable -> DOM) with an empty diagonal, and a decode row running invertScrambleMap so text -> ciphertext -> recovered original are all visible at once. The 'one codepoint' option is caught in a try/catch around a direct buildScrambleMap call and prints '[no-ai] charset needs at least 2 distinct codepoints' verbatim, flagged as the one throw that does NOT fail open because it fires inside the service constructor, outside load()'s try/catch. The default textarea content includes '— ünïcodé 😀' so the pass-through characters are byte-identical in both columns.

**Features shown:** buildScrambleMap; scrambleText; invertScrambleMap; randomSeed; DEFAULT_CHARSET; ScrambleMap shape; Derangement guarantee; Bijectivity; Non-charset characters pass through untouched; Space is never ciphered; FAILURE: charset under 2 distinct codepoints does not fail open; Framework-free core

### 5. 4. Stage 3 — The font that undoes it (#stage-3-font)

**Purpose.** Teach the second half of the mechanism — a font whose cmap addresses the plaintext outline by the ciphertext codepoint — and show that this is simultaneously the whole trick and the whole weakness. Same @defer block as Stage 2, sharing its map.

**Interaction.** THE FORGE BENCH. A 'forge it' button runs parseBaseFont(Roboto.ttf) -> forgeScrambledFont(font, map, 'Lab-<seed>-<charsetHash>') -> new FontFace -> document.fonts.add, printing measured numbers: .ttf bytes fetched, parse ms, forge ms, forged bytes, FontFace.load ms, glyphs written. Family names carry a Lab- prefix and a charset hash so they can never collide with the shell or with each other. 'Download the forged font' hands over the ArrayBuffer as a Blob. Four sub-demos: (1) APPLY — the bench ciphertext paints as words; (2) INVERT — the same family applied to ordinary plaintext, which becomes gibberish, proving the font cannot draw its own plaintext codepoints; (3) METRICS — the no-reflow proof done CORRECTLY: the bench paragraph rendered as protected-ciphertext-in-forged-font above and plaintext-in-base-Roboto below, at identical measure with a wrap ruler, so every line breaks at the same word. Never protected-vs-revealed, which reflows and would print a number contradicting its own caption; (4) LETTERFIT — 'AVATAR Wave To fi ffi' at 72px, protected above and base Roboto below, showing the kern/GPOS AND GSUB loss, correcting the README's kerning-only claim. A 0-3s delay slider before the FontFace registers runs two panes side by side — one blanked, one showing raw ciphertext, both resolving to words — which is the only way hideUntilReady is observable once the .ttf is cached. A live document.fonts NoAi-_/Lab-_ family list with the bench's own explicit document.fonts.delete() cleanup, captioned that the library itself does not do this on injector destroy. THE COLLISION DEMO, taken from Proposal 3 in its sequential form: pin the seed, then narrow the charset, and rebuild — the previous face is still registered under the same family because nothing ever removes it, so the new cmap conflicts with it. One knob turn, real observed library behaviour, fully reversible, zero risk to the shell. (The base proposal's simultaneous two-face version is dropped: face selection among same-family FontFaces is browser-defined and may not reproduce.)

**Features shown:** parseBaseFont; forgeScrambledFont; NoAiFontError + .missing; Advance widths preserved glyph-for-glyph; Glyph outlines byte-faithful to the base; Forged font cannot render its own plaintext codepoints; config.hideUntilReady; COST: no kerning, ligatures, or any OpenType feature; COST: uncompressed .ttf plus a runtime forge; FAILURE: familyName collides when two instances share a seed; FAILURE: forged FontFaces are never removed; Framework-free core

### 6. 5. Stage 4 — Wiring it into Angular (#stage-4-angular)

**Purpose.** Now that the mechanism is understood, show the thin Angular layer that applies it, and the four ways to hold it wrong. Uses the SHELL service through the root injector — no provideNoAi, no child injector, so this section adds zero constraint-5 exposure and can render eagerly.

**Interaction.** Three live panels, each with the exact source that produced it beneath and a live textContent readout beside: <p noAi>literal</p>, <p [noAi]="bound">, and <h3 noAiFont>{{ text | noAi }}</h3>. One text input feeds the bound and piped panels so ciphertext regenerates per keystroke, which is what makes the impure pipe observable; flipping #see-it's reveal re-runs it with no input change, which a pure pipe could not do. Then a 'four ways to hold it wrong' strip, each a live before/after pair: pipe WITHOUT noAiFont (permanently visible gibberish, the first-day mistake); [noAi] on content containing <strong> and a real <a href> (formatting gone, link dead) beside the same content built from per-node pipe + noAiFont (intact, link live); [noAi] bound to an input the visitor can clear to '' (the previous sentence stays on screen, with the `if (bound) this.original = bound` guard shown and the reason it exists); and the element's live style attribute printed verbatim to show the library ships no stylesheet. The directive-vs-interpolation conflict is stated as the prescribed rule in prose beside the two correct forms rather than staged as a race.

**Features shown:** NoAiDirective — element-content form; NoAiDirective — bound form; NoAiDirective input default ''; NoAiFontDirective; NoAiPipe (impure); service.scramble; Inline styles only; FAILURE: pipe without noAiFont; FAILURE: NoAiDirective destroys child markup; FAILURE: [noAi] bound to '' leaves stale text

### 7. 6. Stage 5 — Server render and this page's baked seed (#stage-5-ssr)

**Purpose.** Close the loop and turn the static-hosting caveat from a below-the-fold footnote into a section that proves gate 3's marked row. The strongest single idea in the batch: the page verifies its own claims in public and would visibly fail if the library or the deploy ever drifted.

**Interaction.** Live re-fetch of location.href with the protected run, the data-no-ai-ssr attribute and the inline visibility:hidden each highlighted and labelled in the response — delivering the highlighting the original spec promised and the shipped component never implemented. If the fetch fails, the fallback panel is loud and red, never a quiet degrade to document.textContent, because a silently faked 'what the server sent' panel would poison every other claim on the page. Beside it, the page reads its own <script id="ng-state">, prints the real noAiSeed, and runs THREE LIVE ASSERTIONS with visible PASS/FAIL: (1) transferred seed === service.map.seed; (2) familyName === 'NoAi-' + seed.toString(36); (3) buildScrambleMap(bakedSeed) rebuilt client-side reproduces the exact ciphertext already sitting in the prerendered HTML. Assertion 3 is the determinism proof — a browser-built map matching a Node prerender's output — and the SSR/hydration contract, on a page with no server. Then the gate-3 table repeated with the static row marked and one unhedged sentence: this number is the same for you as for everyone else, and will be until the next deploy. A side note contrasts it with Stage 2's bench, which draws a fresh seed whenever you ask, and names what per-request SSR would give you instead.

**Features shown:** TransferState seed handoff ('noAiSeed'); service.familyName; service.map; Determinism — same seed, same cipher everywhere; Server-rendered HTML is scrambled for JS-less crawlers; data-no-ai-ssr marker and hydration double-scramble avoidance; FAILURE: prerendering bakes one seed for every visitor; config.seed

### 8. 7. Break it in front of you (#break-it)

**Purpose.** Demonstrate the technique's own defeat, timed, using only exported functions. Nothing else on the page earns as much trust, and a page that will not show its own break has not earned any of its other claims.

**Interaction.** ATTACK A — needs the seed, works on this page: read noAiSeed from ng-state, buildScrambleMap, invertScrambleMap, decode the live .protected-body textContent, print the recovered paragraph and elapsed microseconds beside the six lines that did it. ATTACK B — needs nothing but the font file, the general case: take the ArrayBuffer forged in Stage 3 and recover the substitution WITHOUT the seed by matching each forged glyph's path back to the base font's glyph with the same outline; the base glyph's unicode is the readable character, the forged glyph's unicode is the scrambled one. Print the reconstructed table and elapsed ms. This replaces Proposal 1's 're-read the cmap and invert' route, which cannot work: forgeScrambledFont names every glyph uni<scrambled> and the cmap maps scrambled -> outline, so the cmap alone never reveals which readable letter an outline draws. Fallback if path-command equality is unreliable after serialization: match on (advanceWidth, rounded bounding box), which font-forge.spec.ts already asserts is preserved to within one unit on a 2048-unit em; the panel states which method it used. Honest nuance no other proposal stated: on THIS deployment the forged font is never served as a network resource, it is built in memory, so attack B is the attack against any site that ships a pre-forged font file — while attack A is the attack against this one, because the seed is in the HTML. Closing threat model, unhedged: stops fetch+parse, innerText scraping, pasting a page into a chat window, and crawlers that never run JS; does not stop anyone who spends the seconds you just watched, and does not stop OCR. No blind frequency solver — it needs a bundled lexicon on a page whose own argument is about bytes, and attack B is stronger and free.

**Features shown:** invertScrambleMap; buildScrambleMap; parseBaseFont; Bijectivity — losslessly invertible; Determinism; THREAT MODEL: what it stops and what it does not; TransferState seed handoff

### 9. 8. What the mechanism costs (#costs)

**Purpose.** Convert the vague tradeoffs prose into a checklist where every row is an action the visitor performs or a number measured on their machine, each traced back to the stage that caused it. Nothing here is assertable without an adjacent executable proof.

**Interaction.** Every row is a deep link that scrolls to the live control AND sets it to the state that proves the claim (grafted from Proposal 3 — it structurally forbids unfalsifiable claims). DO-IT ROWS with self-tick indicators: Ctrl+F (links to #stage-1-dom); copy-paste (links to #see-it's selection mirror); run your browser's Translate; open Reader Mode; turn on an OS/browser force-fonts override, framed as the cost falling on the low-vision users who depend on that setting, not as a party trick; disable JS and reload, plus an <iframe sandbox="" srcdoc> over the already-fetched HTML string from Stage 5 so scripts are blocked and the paragraph is genuinely, verifiably blank. MEASURED ROWS pulled from Stage 3's forge — bytes fetched, parse ms, forge ms, forged bytes, FontFace.load ms — with a stated 3-4x mobile multiplier and the Core Web Vitals consequence named out loud: hideUntilReady defaults true, so a protected LCP element is gated on the .ttf download plus the forge. Labelled honestly as a warm re-run on an already-cached base font until the library exposes real load timings. A no-JS matrix for hideUntilReady true vs false, quoting the real prerendered style attribute. VISUAL ROWS: the 72px letterfit pair; the same sentence with a matching fallback and a deliberately wrong monospace fallback, word gaps and wrap points visibly different because the space glyph comes from the fallback; and a Polish/German/Japanese specimen with every pass-through character highlighted, since DEFAULT_CHARSET is ASCII 0x21-0x7E only, plus the recipe for extending charset and the hard constraint that a CJK charset needs a megabyte-scale base font forged in the browser. PROSE ROW, unhedged: screen readers announce gibberish, and that is the mechanism working — any readable copy anywhere in the HTML would hand a scraper the plaintext; protect article bodies, leave nav, headings and anything AT needs unprotected. LAST ROW: what this library does nothing about — RSS full-text, og:description, JSON-LD articleBody, AMP/print views, headless JSON APIs.

**Features shown:** COST: find-in-page; COST: copy-paste; COST: no kerning/ligatures/GSUB; COST: word spacing comes from the fallback font; COST: uncompressed .ttf plus runtime forge; COST: screen readers announce gibberish; Non-charset characters pass through untouched; config.fallbackFontFamily; FAILURE: JavaScript disabled means blank space; service.hidden

### 10. 9. Every knob, running live (#knobs)

**Purpose.** A gallery of real provideNoAi child injectors, arriving only after the reader knows what each knob acts on. Kept as a GALLERY rather than folded into a single reconfigurable bench: side-by-side is how a visitor notices that a wrong fallback moved the word gaps, whereas toggle-and-remember across a 250ms rebuild is how they miss it.

**Interaction.** Behind @defer (on interaction) — an explicit 'build these instances' button. Interaction triggers cannot fire during prerender under any circumstance, which is strictly stronger than the current (on viewport) guard against the shared-SEED_KEY clobber, and it kills the self-invalidating 'Scroll down to build four more fonts…' placeholder in one move. One card per config field, each a real createEnvironmentInjector with its own hardcoded distinct seed drawn from a reserved band that never includes the shell's: config.font as all three NoAiFontSource forms (shared ArrayBuffer, loader thunk, assetUrl string) plus one deliberately mismatched serif base; fallbackFontFamily matching vs serif on the same sentence; charset digits-only with a plain/protected split view so the reader can see exactly which characters moved (fixing today's invisible demo); hideUntilReady paired with a delayed loader; disabled as the kill switch, with its DOM readout showing plaintext and aria-hidden dropped because nothing there is protected. Each card prints inject(NO_AI_CONFIG) as resolved JSON, so the defaults are demonstrated rather than asserted, plus a six-field live signal dashboard (ready/failed/active/revealed/hidden/fontStack) — the delayed card is where active()===true while ready()===false is visible, and the failure cards are where ready() && failed() coexists with hidden()===false. Then the FAILURE GALLERY, every entry real and caught, each printing its message verbatim next to text that has gone readable rather than blank: an absolute '/fonts/Roboto-Regular.ttf' that genuinely 404s under the /no-ai/ base href, beside the same card fixed with assetUrl(); a rejecting loader thunk; four garbage bytes through parseBaseFont; a real .woff2 through parseBaseFont; and charset [0x61,0x62,0x4e2d] against Roboto printing NoAiFontError.missing === ['中']. No whole-page sabotage button — the per-instance cards prove fail-open just as well and cannot swallow the page or leave a visitor looking at an inverted central claim.

**Features shown:** provideNoAi(config) — per-injector instances; NO_AI_CONFIG / ResolvedNoAiConfig; NoAiFontSource — all three forms; config.font; config.fallbackFontFamily; config.charset; config.hideUntilReady; config.disabled; service.ready; service.failed; service.active; service.hidden; service.fontStack; service.familyName; service.map; Fail-open on any font error; NoAiFontError + .missing; FAILURE: WOFF/WOFF2 rejected; FAILURE: string font source resolves against the document URL; FAILURE: base font missing a charset glyph

### 11. 10. Verdict (#verdict)

**Purpose.** One place where the technical adoption decision lives, after the reader has personally verified everything it rests on. Short and link-heavy — the disqualifiers already fired in the masthead, so this does not repeat them, it resolves them.

**Interaction.** Three columns: STOPS (bulk fetch+parse, innerText scraping, paste-into-a-chat-window, JS-less crawlers), DOES NOT STOP (anyone who spends the seconds you watched in #break-it; OCR; a JS-executing crawler still gets ciphertext from innerText, which is the actual reason the technique works at all), DOES NOTHING ABOUT (RSS full text, og:description, JSON-LD articleBody, print/AMP views, headless JSON APIs). The service's own doc comment at line 56 ('Unique per load so nothing caches across ciphers') is false in that case. Fixing it turns #stage-3-font's collision demo from a live hazard into a fixed-bug note and lets the #knobs cards stop hardcoding reserved-band seeds.

- **Make the TransferState write first-writer-wins (`if (!transferState.hasKey(SEED_KEY)) transferState.set(...)`) instead of unconditional at no-ai-font.service.ts:92, or let provideNoAi take a key discriminator.** _(small — two lines)_  
  Every NoAiFontService writes to the same module-level SEED_KEY, so a nested provideNoAi rendered on the server overwrites the shell's seed and the client rebuilds the wrong cipher for already-scrambled DOM. This is the single hazard that forces @defer on every section creating a child injector; fixing it downgrades @defer from a correctness requirement to a performance choice and would let #knobs prerender.

- **Register a DestroyRef callback calling document.fonts.delete(face).** _(small)_  
  document.fonts.add(face) at no-ai-font.service.ts:119 is never paired with a delete, so destroying an EnvironmentInjector tears down the service and leaves its face registered for the document's lifetime. #stage-3-font can only demonstrate the leak and do the cleanup by hand — it cannot show the library doing it.

- **Validate the charset in provideNoAi, or catch buildScrambleMap's '<2 distinct codepoints' throw inside the service and route it to failed() like every other error.** _(small)_  
  It fires from the constructor (no-ai-font.service.ts:95), outside load()'s try/catch, so it propagates as an injection failure — a white screen for an adopter whose charset comes from configuration. The bench works around it by validating before calling; a real app cannot.

- **Expose load measurements as a signal: `readonly timings = signal<{ fetchMs; parseMs; forgeMs; faceMs; baseBytes; forgedBytes } \| null>(null)` populated in load().** _(small)_  
  Without it #costs can only report a warm re-run on an already-fetched, already-parsed base font, which is measurably faster than the real cold path and therefore flatters the library on exactly the metric a sceptic said they would check the method on. The page labels it honestly until this lands. It is also the field an adopter wants in their own RUM.

- **Resolve string font sources against document.baseURI rather than a bare fetch(source) at no-ai-font.service.ts:32. MUST land in the same change as the #knobs 404 card, which would otherwise start passing.** _(small, but coupled — fix and demo ship together)_  
  A relative string resolves against location.href and an absolute one 404s under a subpath — the only reason projects/demo/src/app/font-source.ts's assetUrl() exists. If fixed, the demo card must switch to a genuinely missing filename or the page will demonstrate a bug that no longer exists.

- **README corrections, because the page will now contradict it in public and a README that disagrees with the demo is a named distrust trigger: forgeScrambledFont's snippet takes a PARSED Font and needs parseBaseFont first (as written it would not compile); the seed default is not 'random per page load' under SSR or prerendering; the install command names an unpublished package; 9 of 18 exported symbols are undocumented (parseBaseFont, NoAiFontError, invertScrambleMap, randomSeed, DEFAULT_CHARSET, NO_AI_CONFIG, ResolvedNoAiConfig, NoAiFontSource, ScrambleMap); the runtime-state list omits fontStack/hidden/map/familyName; the cost list omits GSUB/ligature loss, fallback-driven word spacing, textContent destroying child markup, relative font URLs, and the two throws that do not fail open.** _(medium — 15 discrete corrections)_  
  #adopt links to the README as the reference. Shipping this page against the current README means a visitor who follows the link finds a document that contradicts what they just verified.

- **DO NOT narrow `revealed` or `failed` to readonly — but note the page does NOT depend on this the way Proposal 1 did. The plan writes only `revealed`, which the service's own doc comment (no-ai-font.service.ts:65-68) already documents as a demo/debug switch. Nothing writes `failed`; the whole-page sabotage button is dropped.** _(none — a constraint removed, not added)_  
  Freezing a library's public API to preserve a demo gimmick inverts the relationship between the two. This plan removes that dependency rather than asking the library to honour it.

## Judge disagreements and how they were resolved

The panel did not reach consensus; each lens crowned a different design. These are the
substantive conflicts and the call made on each.

- **Which proposal to base on. The feature-completeness judge ranked Proposal 1 first and Proposal 4 second; the decision judge ranked Proposal 4 LAST (5/10) and Proposal 2 first; the buildability judge ranked Proposal 4 first (9/10) and Proposal 2 last.**  
  Base on Proposal 4 — it has the highest total (22 vs 21/21/21), wins buildability outright, and places second on completeness. Its two named defects are both surgical grafts rather than rewrites: the decision judge's complaint (adoption facts scattered across positions 8 and 11 with no consolidated verdict) is fixed by hoisting Proposal 2's gates to the masthead and adding a consolidated #verdict; the completeness judge's complaint (SEO absent entirely, plus a large fraction of the config surface arriving in a late deferred gallery) is fixed by grafting Proposal 2's search-index pane into #stage-1-dom and by moving all interactive config exploration into the two above-the-fold benches, leaving #knobs to do only what a gallery does better than a console — simultaneous comparison. Proposal 1 was not chosen despite its 9/10 on completeness because at eleven sections with eight bespoke rungs plus a cross-page evidence ledger it is the largest build, it withholds the verdict until section 9 of 11 (engagement-before-gates), and its marquee attack is provably broken.

- **Does the reveal toggle reflow? The completeness judge praised Proposal 3's measured 'lines reflowed: 0' readout across the reveal toggle as a highlight; the buildability judge called it a shipped bug that would print a number contradicting its own caption.**  
  Buildability judge is right, verified in source. font-forge.ts:65 registers `advanceWidth: source.advanceWidth` — the READABLE glyph's width — under the SCRAMBLED codepoint. Those widths therefore hold only while the forged font is applied; withholding it repaints the ciphertext at the fallback's own natural widths and the paragraph WILL reflow. The advance-width proof must compare ciphertext-in-forged-font against plaintext-in-base-font, which is exactly what Proposal 4 specified and what this plan keeps. Better still, the reflow on reveal is inverted into a demonstration: the lines move because the forged font was supplying the plaintext's metrics.

- **Attack B. The completeness judge treated Proposal 1's 'forge the font, re-parse it, read the cmap back, invert' as coverage of the downloadable-font weakness; the buildability judge proved it cannot work.**  
  Buildability judge is right, verified in source. forgeScrambledFont names every glyph `uni${scrambled}` (font-forge.ts:63) and sets `unicode: scrambled`, so the forged cmap maps scrambled codepoint -> outline and never reveals which readable letter that outline draws. Replaced with Proposal 4's fallback, which is a genuine and correct attack: match each forged glyph's path (or advanceWidth + bounding box) back to the base font's glyph, whose unicode is the readable character. Added nuance no proposal stated: on THIS deployment the forged font is never served as a file, so attack B is the attack against sites that ship a pre-forged font, while attack A — read the seed from ng-state — is the attack against this one.

- **Where the long specimen's plaintext should live. Proposal 2 wanted a Node prebuild step pre-scrambling it into an asset; the buildability judge listed that step as must-not-survive.**  
  Take the fallback both parties endorsed: keep the specimen as template content in one JS chunk, extend verify-static-build.mjs to pin it there and keep it out of index.html, and disclose it plainly on the page. The prebuild would thread a build-time seed into provideNoAi({seed}) and produce pre-scrambled markup that must interact correctly with readOriginalFromDom()'s inversion path and the data-no-ai-ssr marker — a new pipeline welded to the library's most fragile code, for a benefit disclosure already provides.

- **Whether to put a plaintext 'sandbox specimen' in the prerendered HTML so the cipher bench has default content. Proposal 4 wanted it with a build-guard assertion that it is present; the decision judge listed it as must-not-survive.**  
  Decision judge is right — a view-source skim does not read on-page labels or HTML comments, and finding readable prose in a document arguing that readable prose is the vulnerability costs more trust than a convenient default is worth. Resolved by wrapping both benches in @defer (on immediate): deferred blocks render only the placeholder during prerender, so no bench content reaches index.html, while on the client they trigger immediately and remain effectively above the fold. This also removes the hydration-mismatch risk of populating an eagerly-rendered textarea client-side.

- **Whether to keep a computed adoption verdict in the first screen. The decision judge scored Proposal 2 highest largely for its three gates, then named the verdict pill and questionnaire as must-not-survive.**  
  Keep the gates, drop the instrument. Three static, unmissable rows carrying the real numbers — peer range, AGPL §13 with a yes/no on dual licensing, and the rendering table with this page's row marked — deliver a correct NO in thirty seconds without a machine issuing the reader an identity it cannot know, and without gating any demonstration behind an answer.

- **@defer trigger for child-injector sections: (on viewport) in the current page and Proposals 2 and 4, (on idle) in Proposal 3, (on interaction) in Proposal 1.**  
  (on interaction) for #knobs — an explicit 'build these instances' button. Viewport and idle triggers are browser-only by convention; an interaction trigger cannot fire during prerender under any circumstance, so it is a strictly stronger guarantee against the shared-seed clobber, and it simultaneously kills the self-invalidating 'Scroll down to build four more fonts…' placeholder. (on immediate) for the benches, which instantiate no service and so are not subject to constraint 5 at all.

- **One reconfigurable instance (Proposal 3) versus a gallery of simultaneous instances. The completeness judge scored Proposal 3 lowest specifically for converting every comparison into toggle-and-remember; the decision judge scored it second for the same architecture.**  
  Split by what each does best. Interactive configuration of the cipher and the forge lives in the benches, where it costs nothing because no service or injector is involved. Comparisons that only land side by side — matching versus wrong fallbackFontFamily, hideUntilReady true versus false, three NoAiFontSource forms, five failure modes — stay a simultaneous gallery in #knobs. Proposal 3's genuinely superior collision demo (pin seed, narrow charset, rely on the never-deleted previous face) is grafted into the bench, where one knob turn reproduces both the familyName collision and the FontFace leak with no second concurrent instance.

## Risks

- **Constraint 5 — a child injector instantiated during prerender writes to the shared 'noAiSeed' key and garbles the shell after hydration. This plan has more provideNoAi instances than today (nine or so cards plus the failure gallery).**  
  _Mitigation:_ The entire interactive spine — both benches and #break-it — uses the exported framework-free core with NO EnvironmentInjector and NO NoAiFontService, so it touches TransferState zero times. #stage-4-angular uses the SHELL service through the root injector and creates nothing. The only provideNoAi calls live in #knobs behind @defer (on interaction), which cannot fire during prerender under any circumstance — strictly stronger than today's (on viewport). Backed by the new build-guard check counting data-no-ai-ssr elements in dist index.html.

- **Constraint 3 — readable protected text reaching the served HTML. The plan multiplies the surfaces where plaintext appears at runtime: the selection mirror, the self-calibrating search, the innerText panel, the SEO pane, the bench's decode row, the METRICS plaintext twin, and both attack outputs.**  
  _Mitigation:_ All of them are client-populated only. Both benches sit in @defer (on immediate) with a skeleton placeholder, so no bench prose — including the METRICS plaintext twin and the default textarea content — reaches index.html; this is what replaces the base proposal's deliberately-plaintext sandbox specimen, which a view-source skim would have found. The search box never names a word: the visitor supplies it from their own eyes. #break-it output nodes render empty on the server and are populated only from click handlers, asserted empty in dist by the guard.

- **The ~700-word specimen's plaintext still ships in one emitted JS chunk, because it is template content. Today's guard greps index.html only, so this passes silently, and a sceptic's stated first move is view-source.**  
  _Mitigation:_ Judge disagreement resolved toward disclosure over a build pipeline. The guard is extended to pin the phrase to at most one .js chunk, and #stage-1-dom states it plainly: this specimen's plaintext is in our bundle because it is template content; on a real site the article body arrives from your CMS as data. The alternative — a Node prebuild that pre-scrambles the specimen — was rejected: it welds a new pipeline to readOriginalFromDom()'s inversion path and the data-no-ai-ssr marker, the library's most delicate code, for a benefit disclosure already delivers.

- **Constraint 6 — familyName derives from the seed alone, so any two forged instances sharing a seed register conflicting cmaps under one family in document.fonts.**  
  _Mitigation:_ The benches never use NoAiFontService and name their own faces 'Lab-<seed>-<charsetHash>', so they cannot collide with the shell or each other. Every #knobs card carries an explicit hardcoded distinct seed from a reserved band that never includes the shell's. The hazard is demonstrated only inside the bench, sequentially (pin seed, narrow charset), where both faces are ours and the state is reversible. A demo spec asserts all allocated seeds are distinct.

- **#break-it attack B depends on matching forged glyph paths back to base-font glyphs. forgeScrambledFont reuses source.path by reference so serialization should round-trip, but this is unverified against opentype.js's own output.**  
  _Mitigation:_ Three-deep fallback, decided during implementation and reported on the panel itself. First: exact path-command comparison. Second: match on (advanceWidth, rounded bounding box), which font-forge.spec.ts already asserts is preserved to within one unit on a 2048-unit em, with path commands used only to disambiguate ties. Third: drop attack B entirely — attack A is fully independent, requires nothing but ng-state, and carries the section on its own.

- **The reveal toggle in #see-it reflows the paragraph, because the fallback supplies its own advance widths once the forged font is withheld (verified: font-forge.ts:65 copies the READABLE glyph's advanceWidth onto the SCRAMBLED codepoint). Three of the four proposals captioned this as 'lines reflowed: 0' and would have printed a number contradicting their own caption in the page's most trust-sensitive interaction.**  
  _Mitigation:_ Caption the reflow as evidence, not as a defect: the lines move precisely because the forged font was carrying the plaintext's metrics. The advance-width preservation claim is proved separately in #stage-3-font by comparing ciphertext-in-forged-font against plaintext-in-base-Roboto — never protected against revealed.

- **Performance numbers taken by re-running parse and forge in the bench are warm-path figures on an already-cached .ttf, and presenting them as 'what this costs your readers' flatters the library on the metric a sceptic said they would check the method on.**  
  _Mitigation:_ Label them unmistakably as a warm re-run with the base font already fetched, and state the cold-path components separately from resource timing where available. Ship the recommended timings signal on NoAiFontService and switch #costs to real numbers as soon as it lands.

- **Scale. Eleven anchored sections, two benches, a gallery and a narrative track is comparable in size to the current nine-component page plus roughly two new benches. Under-building it produces a page that is differently all-over-the-place.**  
  _Mitigation:_ Build order that keeps the page shippable at every step: (1) masthead gates + #see-it selection mirror + #stage-1-dom, reusing proof-section's specimen machinery; (2) #stage-5-ssr and #break-it attack A, reusing raw-html-section's fetch; (3) #costs as a checklist over existing tradeoffs content; (4) the two benches as one @defer block; (5) #knobs by refitting config-lab and config-card, which already do 80% of the work; (6) #verdict and #adopt by refitting tradeoffs-section and install-section. Attack B and the collision demo are last and optional.

- **@defer (on immediate) for the benches costs a frame or two of above-the-fold content compared with rendering them eagerly, and the placeholder skeleton must not read as broken.**  
  _Mitigation:_ Accepted deliberately: keeping bench prose out of the prerendered HTML is worth more than the frames. The placeholder is a neutral skeleton with no instructional copy — never 'scroll down to…' — and the benches sit below #see-it and #stage-1-dom, both of which render eagerly, so the first screen is never a skeleton.

- **Zoneless change detection. The selectionchange listener, the MutationObserver on the outerHTML readout, file-picker callbacks and async forge results are all native callbacks outside Angular's template bindings.**  
  _Mitigation:_ Every one writes to a signal, which schedules change detection under zoneless. No manual ApplicationRef.tick anywhere. The bench's initial seed is a hardcoded constant, never randomSeed(), so nothing depends on server/client agreement it cannot have.

- **Constraint 8 — #costs invites the visitor to enable a forced-font accessibility override, a setting real users depend on, as a demonstration aimed at sighted developers.**  
  _Mitigation:_ Framed as what it is: the cost falling on the users who need that setting most. Every accessible string on the page describes specimens and never reproduces them, and aria-hidden is applied per specimen only when that specimen is actually ciphered under its current config.

- **Gate 3's rendering table and #stage-5-ssr could drift apart, or the masthead could become wrong if the deploy ever stops prerendering.**  
  _Mitigation:_ Every seed statement is derived from a runtime ng-state read, never from a build constant, so the sentence stays true if the render mode changes. Gate 3's 'this page, right now' marker is computed from the same read, and the guard asserts index.html contains a noAiSeed key.

## What this design gives up

- A guided adoption verdict. The reader must read three gate rows and classify themselves; the page will not do it for them. A skimmer can still scroll straight past all three into the demonstrations. This is a deliberate trade of conversion efficiency against not shipping an instrument that assigns a reader an identity from three answers it cannot validate.

- A single unified console. Configuration exploration is split — the cipher and the forge are fully turnable in the benches, but fallbackFontFamily, disabled, the three NoAiFontSource forms and every failure mode are fixed gallery cards in #knobs, not live knobs. A visitor who wants to try a fallback family the page did not think of cannot. Deliberate: simultaneous comparison beats toggle-and-remember, and it keeps the injector count fixed and every seed hardcoded and distinct.

- Progress gamification. No evidence ledger, no 'proofs you have run: 3 / 8' counter. Nothing tells a visitor which demonstrations they have not tried, so someone who reads only the first two stages will genuinely miss the failure gallery. Traded for eight fewer coupled components and no cross-section coordination state.

- Whole-page sabotage. There is no button that takes the entire document to plaintext, so the fail-open path is only ever watched at instance scale in #knobs, not at page scale. Traded to avoid leaving a visitor looking at the page's central claim inverted with no indication it is simulated, and to avoid making the library's public API a hostage to a demo interaction.

- A seedless statistical attack. No word-pattern or frequency solver, because it needs a bundled lexicon on a page whose own argument is about bytes. The page therefore never puts a number on 'how long would this take an attacker who has only the ciphertext'. Attack B (recover the substitution from the font file) is stronger and free, but it answers a different question.

- Honest cold-path performance numbers, until the library exposes load timings. #costs reports a warm re-run on an already-fetched base font and says so. The number a content-site owner will actually be judged on — cold LCP with the .ttf download in the critical path — is described but not measured.

- Full plaintext hygiene for the demo's own specimen. The ~700-word article ships readable in one JS chunk because it is template content. The guard pins where it may appear and the page discloses it, but a sceptic who greps the bundles will find it. The only alternative was a build pipeline welded to the library's most fragile code path.

- Screen-reader cost stays prose, permanently. It cannot be demonstrated without a readable copy in the served HTML, which is the thing the technique exists to prevent.

- The nested-provideNoAi-during-SSR hazard stays prose, and the demo continues to pay for it with @defer. The page says so and lists it as a known issue rather than hiding it, but it cannot show the bug without shipping a broken prerender.

- Above-the-fold immediacy for the benches. @defer (on immediate) costs a frame or two versus eager rendering, in exchange for keeping bench prose out of the prerendered HTML.

- Any claim that the library is production-mature. The page states v0.0.1, an unpublished package, a peer range that excludes essentially every Angular app in production today, and four published known issues. Some readers will correctly conclude no. That is the intended outcome of the gates, not a failure of them.
